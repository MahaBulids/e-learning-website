What are Exceptions in Java?

An exception in Java is an unwanted event that disrupts the normal flow of a program. It usually occurs during runtime (like dividing by zero, invalid input, file not found). Java uses a robust Exception Handling mechanism to deal with such situations without crashing the program.

Java provides try, catch, finally, throw, and throws keywords to handle exceptions.

Why Exception Handling?

  • Avoids abnormal termination of the program.
  • Makes debugging easier.
  • Improves program reliability and maintainability.
  • Helps separate error-handling code from normal business logic.

Types of Exceptions in Java

Java exceptions are categorized mainly into three groups:

  • 1. Checked Exceptions (compile-time)
  • 2. Unchecked Exceptions (runtime)
  • 3. Errors (serious problems, not usually handled)

1. Checked Exceptions

These are exceptions that the compiler checks at compile-time. If not handled, your code will not compile. They usually occur due to external factors (like file handling, database connection). 

// Example: Checked Exception
import java.io.*;

class Example {
    public static void main(String[] args) {
        try {
            FileReader file = new FileReader("missing.txt"); // file may not exist
            System.out.println("File opened successfully");
        } catch (IOException e) {
            System.out.println("File not found: " + e);
        }
    }
}

Examples: IOException, SQLException, FileNotFoundException

2. Unchecked Exceptions

These are not checked by the compiler. They occur at runtime due to logic errors or invalid operations (like dividing by zero or null reference). 

// Example: Unchecked Exception
class Example {
    public static void main(String[] args) {
        try {
            int a = 10 / 0; // division by zero
        } catch (ArithmeticException e) {
            System.out.println("Error: " + e.getMessage());
        }
    }
}

Examples: ArithmeticException, NullPointerException, ArrayIndexOutOfBoundsException

3. Errors

Errors are serious issues that cannot be recovered by the program. They usually occur in the JVM (Java Virtual Machine) and are beyond programmer’s control. Example: memory leaks, system crashes. 

// Example: Error (StackOverflowError)
class Example {
    public static void recursive() {
        recursive(); // infinite recursion
    }
    public static void main(String[] args) {
        recursive(); // will throw StackOverflowError
    }
}

Examples: OutOfMemoryError, StackOverflowError, VirtualMachineError

Java Exception Hierarchy

At the top is Throwable, which has two main branches:

  • Exception → includes Checked & Unchecked Exceptions (can be handled).
  • Error → serious issues (not usually handled).

Exception Handling Syntax

try {
    // risky code
} catch(ExceptionType e) {
    // handling code
} finally {
    // optional block, always executes (cleanup code)
}
